Prompt Engineering 课程

这是与 Harness Engineering 课程平行的一条学习线。注意课程名——是 Prompt Engineering，不只是"写 prompt"。

写一个 prompt 是"术"，prompt engineering 是"工程"。前者关注"这句话怎么写"；后者关注"怎么可复现地得到好结果，并系统地持续改进"——它多出来的是评估、迭代、防御、版本管理这些让结果稳定可靠的工程环节。这门课教的是后者。

四个阶段

课程分四个阶段，从"把话说清楚"一路走到"把 prompt 当代码来维护"：

阶段一 · 基础

  1. 第 0000 课：什么是 Prompt Engineering —— 它和"写 prompt"到底差在哪；工程化的五个环节与迭代循环。
  2. 第 0001 课：Prompt 的解剖学 —— 一个 prompt 的五个部件，以及 system / user 的分工。

阶段二 · 核心技巧（把结果做对）

  1. 第 0002 课：清晰与具体 —— 消除歧义的六个技巧。
  2. 第 0003 课：少样本与示例 —— 用例子代替长篇解释。
  3. 第 0004 课：思维链（CoT）—— 让模型"想清楚再答"。
  4. 第 0005 课：结构化输出 —— 稳定地吐出 JSON。

阶段三 · 工程方法（把结果做稳）⭐ 这是 “Engineering” 的核心

  1. 第 0006 课：评估 —— 建测试集、给 prompt 打分，让"好不好"可度量。
  2. 第 0007 课：迭代循环 —— 改一处 → 跑一批 → 对比 → 保留更好的。
  3. 第 0008 课：失败模式与防御 —— 幻觉、越权、提示注入。
  4. 第 0009 课：模板化与版本管理 —— 把 prompt 当代码来维护。

阶段四 · 落地

  1. 第 0010 课：接入 Agent —— 把这套方法用进 Harness 课程的 Agent 里。
很多"prompt 教程"只覆盖到阶段二就结束了——那只是"会写"。阶段三才是把它变成工程的关键：没有评估你就不知道改动是变好还是变坏，没有迭代循环你就只能碰运气，没有版本管理你就会把上周更好的那版弄丢。

这门课的约定

  • 语言：除专业名词外全部中文。
  • 模型：示例以 DeepSeek 为准（OpenAI 兼容接口），但 prompt 原则与厂商无关。
  • 可迁移：这里学到的每个套路，都能直接用进 Harness 课程里的 Agent。
