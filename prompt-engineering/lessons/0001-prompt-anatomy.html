第 0001 课：Prompt 的解剖学

很多人写 Prompt 靠"感觉"——想到哪写到哪，效果好不好全凭运气。这一课我们把 Prompt 拆开：一个高质量 Prompt 由五个部件组成。搞清楚每个部件干什么，你就能像搭积木一样，稳定地写出好 Prompt，而不是碰运气。

写 Prompt 的本质，是替一个什么都懂、但什么都不知道你要什么的实习生写工单。它知识渊博（预训练），但对你的具体任务、语气、格式偏好一无所知。你给的信息越结构化、越明确，它交付得越准。

一个反面例子

先看一条几乎所有人都写过的"坏 Prompt"：

帮我写一下这个产品的介绍

模型只能瞎猜：什么产品？给谁看？多长？什么语气？要不要卖点？于是它给你一段四平八稳、放之四海皆可的"正确的废话"。问题不在模型，在于你没给它足够的约束。

Prompt 的五个部件

不是每条 Prompt 都要五个部件全上。但当结果不理想时，对照这五项逐个检查缺了哪个，往往一补就好。

① 角色（Role）

给模型一个身份，等于一次性设定了它的视角、语气和知识侧重。"你是一位面向开发者的技术文案" 和 "你是一位面向宝妈的带货主播"，写出来的东西天差地别。

② 任务（Instruction）

核心动词要明确：是"写"、"改写"、"总结"、"翻译"、还是"挑错"？把模糊的"处理一下"换成精确的动作。

③ 上下文（Context）

模型不知道你脑子里的信息。产品叫什么、卖点是什么、给谁看——这些它猜不到的，必须喂给它。

④ 示例（Examples）

与其用三段话描述你想要的风格，不如直接给一个例子。"照着这个样子写"是最高效的指令之一（下一课会专门讲）。

⑤ 输出格式（Output Format）

不指定，模型就自由发挥。你要 200 字以内、要三个要点、要 JSON——提前说清楚，省得来回返工。

把反面例子改好

用五个部件重写开头那条"坏 Prompt"：

你是一位面向开发者的技术文案。                    ← ① 角色

请为下面这款产品写一段介绍。                      ← ② 任务

产品：一个叫 QuickAPI 的工具，                     ← ③ 上下文
能把 OpenAPI 文档一键转成可调用的 TypeScript SDK。
目标读者：正在找 API 客户端方案的前端工程师。

参考这段的语气（简洁、点出痛点）：                 ← ④ 示例
"还在手写 fetch？QuickAPI 让你少写 80% 的样板代码。"

要求：150 字以内，Markdown，先痛点后卖点。         ← ⑤ 输出格式

同一个模型，拿到这两条 Prompt，输出质量的差距是数量级的。差别不在模型，在于你有没有把"工单"写清楚。

system 与 user：两个角色的分工

在调 API 时，Prompt 通常拆进两个角色。理解它们的分工，是从"聊天框里贴 Prompt"进阶到"工程化用 Prompt"的关键一步：

  • system（系统提示）：设定稳定不变的部分——角色、总体规则、输出格式约束。它像 Agent 的"人格设定"，一次设定、贯穿整段对话。
  • user（用户消息）：放每次都变的部分——这一轮的具体任务和输入。

用第 0002 课的 DeepSeekModel（OpenAI 兼容接口）来看就很直观：

const res = await client.chat.completions.create({
  model: "deepseek-chat",
  messages: [
    // system：稳定的角色 + 规则 + 格式（部件 ①⑤）
    {
      role: "system",
      content: "你是一位面向开发者的技术文案。回答控制在 150 字以内，用 Markdown，先痛点后卖点。",
    },
    // user：每次变化的任务 + 上下文 + 示例（部件 ②③④）
    {
      role: "user",
      content: "为 QuickAPI 写一段介绍。它能把 OpenAPI 文档一键转成 TypeScript SDK，读者是前端工程师。",
    },
  ],
});
为什么要拆开？因为 system 是可以复用和缓存的。在一个 Agent 里，"人格设定"（system）写一次，之后每一轮对话只需要换 user。这正好呼应 Harness 课程里 Agent 的 systemPrompt 字段——它设定一次，贯穿整个循环。

三条立刻能用的原则

  1. 具体 > 客气。"请尽量写好一点"没有信息量；"150 字以内、先痛点后卖点"才有。
  2. 给约束，而非给期望。不要"写得专业些"，要"用第二人称、不用感叹号、每段不超过两句"。
  3. 结果不对，先查五部件。八成是漏了角色、上下文或输出格式中的某一个。

小测验

第 1 题

"帮我写一下这个产品的介绍"这条 Prompt 最主要缺了什么？

缺少礼貌用语，模型会不高兴
缺少上下文、受众和输出格式等约束
用了中文，应该用英文写 Prompt
没什么问题，是模型能力不够

第 2 题

关于 system 和 user 消息的分工，下面哪个说法是对的？

system 放每轮都变的具体任务，user 放固定规则
system 放稳定的角色和规则，user 放每轮变化的任务
两者完全一样，随便放哪个都行
system 只能写英文，user 只能写中文

动手任务

  1. 挑一条你最近随手写过的 Prompt，用五部件逐项检查，补全缺失的部分，对比前后输出。
  2. 把它拆成 system + user 两段：哪些内容属于"设定一次就不变"的 system？
  3. 把这段 system 填进 Harness 课程里 Agent 的 systemPrompt，让你的 Agent 带上这个"人格"。
