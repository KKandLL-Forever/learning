第 0000 课：什么是 Prompt Engineering

在写第一条 prompt 之前，先分清一件容易混淆的事：「prompt」和「prompt engineering」不是一回事。搞混它，你会以为"会写几句话"就等于掌握了这门手艺——而真正让 prompt 在生产环境里可靠工作的，是后面那个 engineering。

一张表看清区别

Prompt（提示词） Prompt Engineering（提示工程）
是什么 一个名词：你发给模型的那段输入 一门方法论：设计→测试→评估→迭代的实践
关注点 "这句话怎么写" "怎么可复现地得到好结果，并持续改进"
类比 一行代码 软件工程（需求→设计→测试→评估→迭代）
产出 一段文字 一套可度量、可迭代、可复用的流程
一句话记住：写出一个能用的 prompt 是"术"，把它变成可靠、可维护、可持续改进的系统才是"工程"。这门课教的是后者。

为什么"会写"还不够

假设你调好了一条 prompt，某次跑出来效果惊艳。问题来了：

  • 它是稳定惊艳，还是这次碰巧？换一批输入还成立吗？
  • 你想改进它，改完之后怎么知道是真变好了，而不是"感觉好了"？
  • 同事把它改了一版，你俩谁的更好？拿什么证据说话？
  • 上线后有人用奇怪的输入把它带偏了（提示注入、越权），你怎么防？
  • 三个月后你想回到"上个月那版更好的"，还找得回来吗？

这些问题，靠"把话写得再漂亮"都解决不了。它们需要的是工程手段：测试集、评估指标、迭代循环、防御设计、版本管理。

Prompt Engineering 的五个环节

  1. 设计：写出候选 prompt（第 0001～0005 课的技巧都在这一步）。
  2. 测试：准备一批有代表性的输入，把 prompt 跑一遍——而不是只试一条就下结论。
  3. 评估：用明确的指标给结果打分（准确率？格式合规率？人工评分？），让"好不好"变成一个数字。
  4. 迭代：一次只改一处，再走一圈②③，用分数对比决定"留新还是留旧"。
  5. 定版 & 版本管理：达标的 prompt 固化下来、存档、标注版本，将来能回滚、能对比。
看出来了吗？这就是你写代码时那套循环：写 → 跑测试 → 看结果 → 改 → 再跑。prompt engineering 只是把这套成熟的工程纪律，搬到了"用自然语言编程一个概率模型"这件事上。你作为工程师，其实早就会这套心法了。

一个"最小可度量"的例子

不用一上来就搞复杂框架。工程化的第一步，往往只是从"试一条"变成"跑一批 + 打个分"：

// 一个极简的评估雏形：给分类任务的 prompt 打准确率
const testset = [
  { input: "这手机太卡了，退货！", expected: "负面" },
  { input: "物流很快，包装也好", expected: "正面" },
  { input: "还行吧，没什么惊喜",   expected: "中性" },
  // ... 越多越有代表性
];

let correct = 0;
for (const { input, expected } of testset) {
  const output = await runPrompt(input);      // 用你的 prompt 跑这条输入
  if (output.trim() === expected) correct++;
}
console.log(`准确率：${(correct / testset.length * 100).toFixed(1)}%`);
// ← 有了这个数字，你改 prompt 时才知道是真变好，还是自我感觉良好

就这么点代码，你已经跨过了从"写 prompt"到"prompt engineering"最关键的一步：让改进有据可依。后面阶段三的课会把评估、迭代、版本管理逐个讲透。

这门课怎么走

回到课程目录你会看到四个阶段：基础（说清楚）→ 核心技巧（做对）→ 工程方法（做稳）→ 落地（进 Agent）。很多教程只到第二阶段就停了——那只是"会写"。这门课的重点在第三阶段。

小测验

第 1 题

下面哪一项最能区分"写 prompt"和"prompt engineering"？

prompt engineering 就是把 prompt 写得更长更详细
prompt engineering 多了评估、迭代、版本管理等让结果可复现的工程环节
prompt engineering 必须用英文写，写 prompt 可以用中文
两者完全一样，只是叫法不同

第 2 题

你把一条 prompt 改了改，感觉输出好像更好了。按工程做法，下一步应该？

直接上线，感觉好就行
在测试集上跑一批，用指标对比新旧两版的分数再决定
再试一条输入，如果也不错就定了
把 prompt 写得更长一点以防万一
