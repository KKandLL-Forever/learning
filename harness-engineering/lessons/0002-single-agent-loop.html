第 0002 课：构建单 Agent 循环

第 1 课我们看了 Harness 的最简形式——一个 while(true) 循环。这一课我们把它扩展成一个结构清晰、可运行、可扩展的单 Agent 循环项目。

一个好的 Harness 不是把逻辑写死在一个文件里，而是拆出清晰的边界：Model Adapter、Tool Registry、Agent Loop。这样你才能在不改核心循环的前提下，换模型、加工具、改 UI。

本课目标

完成本课后，你将拥有一个可运行的 TypeScript 项目，实现以下能力：

  • 工具注册与发现（Tool Registry）
  • Model Adapter 抽象（mock + DeepSeek 两种实现）
  • 流式输出（streaming）
  • 工具执行错误处理
  • 对话历史管理

项目结构

src/0002-single-agent-loop/
├── types.ts      # 类型定义
├── model.ts      # Model Adapter（Mock + DeepSeek）
├── tools.ts      # 工具注册与工具函数
├── agent.ts      # Agent 循环核心
└── main.ts       # 入口示例

核心设计：三个边界

第一步：定义类型

先把循环里流动的数据抽象成类型。注意这里 MessageContent 支持两种形式：纯文本字符串，或 content block 数组（包含 tool_result）。这是一层我们自己的中间抽象，与具体厂商无关。

// src/0002-single-agent-loop/types.ts
export type TextContent = { type: "text"; text: string };
export type ToolResultContent = {
  type: "tool_result";
  tool_use_id: string;
  content: string;
};
export type ContentBlock = TextContent | ToolResultContent;
export type MessageContent = string | ContentBlock[];

export interface Message {
  role: "user" | "assistant" | "system";
  content: MessageContent;
}

export interface ToolDefinition {
  name: string;
  description: string;
  parameters: Record;
}

export interface ToolUse {
  id: string;
  name: string;
  input: Record;
}

export interface Tool {
  definition: ToolDefinition;
  execute(input: Record): Promise | string;
}

export interface ModelResponseChunk {
  type: "text" | "tool_use" | "done";
  text?: string;
  toolUse?: ToolUse;
  result?: AgentResult;
}

export interface ModelAdapter {
  stream(messages: Message[], tools: ToolDefinition[]): AsyncIterable;
}

export interface AgentConfig {
  model: ModelAdapter;
  systemPrompt?: string;
  maxTurns?: number;
}

export interface AgentResult {
  response: string;
  messages: Message[];
  turns: number;
}

第二步：工具注册表

工具是 Harness 的可插拔组件。ToolRegistry 负责三件事：注册工具、查询定义、执行工具并捕获错误。

// src/0002-single-agent-loop/tools.ts
export class ToolRegistry {
  private tools = new Map();

  register(tool: Tool): this {
    this.tools.set(tool.definition.name, tool);
    return this;
  }

  getAllDefinitions(): ToolDefinition[] {
    return Array.from(this.tools.values()).map((t) => t.definition);
  }

  async execute(name: string, input: Record): Promise {
    const tool = this.tools.get(name);
    if (!tool) {
      throw new Error(`未找到工具：${name}`);
    }
    try {
      const result = await tool.execute(input);
      return result;
    } catch (err) {
      const message = err instanceof Error ? err.message : String(err);
      return `工具执行失败：${message}`;
    }
  }
}
工具执行失败不要抛异常终止循环，而是把错误信息作为 tool_result 返回给模型。模型可以据此重试或解释给用户。这是 Harness 韧性的关键设计。

第三步：Model Adapter

ModelAdapter 把不同 LLM 的 API 差异封装起来，让 Agent Loop 只关心统一的数据结构。我们先实现一个不需要 API Key 的 Mock Model，方便学习时直接运行。

// src/0002-single-agent-loop/model.ts（节选）
export class MockModel implements ModelAdapter {
  private turn = 0;

  async *stream(messages: Message[], tools: ToolDefinition[]) {
    const input = this.extractText(messages.at(-1)?.content ?? "");
    this.turn++;

    if (this.turn === 1) {
      yield { type: "text", text: "我帮你查一下北京的天气。" };
      yield { type: "tool_use", toolUse: { id: "tool_1", name: "get_weather", input: { city: "北京" } } };
      return;
    }

    yield { type: "text", text: `根据查询结果，${input}的天气是晴天，温度 25°C。` };
  }
}

同一文件里还包含 DeepSeekModel，它用 OpenAI 兼容 SDK（把 baseURL 指向 https://api.deepseek.com）连接 DeepSeek，并把流式返回的 chunk 转换成我们的 ModelResponseChunk。学完本课后，你只需要把 main.ts 里的 MockModel 换成 DeepSeekModel，就能调用真正的 DeepSeek。

第四步：Agent 循环

这是核心。我们用 async generator 同时做到两件事：

  1. 流式输出：边生成边 yield 文本片段
  2. 循环控制：检测到 tool_use 就执行工具，再把结果塞回历史
// src/0002-single-agent-loop/agent.ts（节选）
async *run(userInput: string) {
  const messages: Message[] = [];
  if (this.config.systemPrompt) {
    messages.push({ role: "system", content: this.config.systemPrompt });
  }
  messages.push({ role: "user", content: userInput });

  for (let turn = 0; turn < (this.config.maxTurns ?? 10); turn++) {
    let turnText = "";
    const toolUses: ToolUse[] = [];

    // 1. 流式接收模型输出
    for await (const chunk of this.config.model.stream(
      messages,
      this.tools.getAllDefinitions(),
    )) {
      yield chunk;
      if (chunk.type === "text") turnText += chunk.text ?? "";
      if (chunk.type === "tool_use") toolUses.push(chunk.toolUse!);
    }

    messages.push({ role: "assistant", content: turnText });

    // 2. 没有工具调用 → 结束循环
    if (toolUses.length === 0) {
      yield { type: "done", result: { response: turnText, messages, turns: messages.length } };
      return;
    }

    // 3. 执行工具，把结果塞回历史
    const toolResultBlocks: ContentBlock[] = [];
    for (const toolUse of toolUses) {
      const result = await this.tools.execute(toolUse.name, toolUse.input);
      toolResultBlocks.push({
        type: "tool_result",
        tool_use_id: toolUse.id,
        content: result,
      });
    }
    messages.push({ role: "user", content: toolResultBlocks });
  }
}

用真实的 DeepSeek 运行（配置 API Key）

当你把 main.ts 里的模型换成 DeepSeekModel 时，就需要一个真实的 API Key 了。第一步，把 .env.example 复制成 .env 并填入你在 DeepSeek 平台申请的 Key：

# .env
DEEPSEEK_API_KEY=sk-你的真实key
DEEPSEEK_MODEL=deepseek-chat
最容易踩的坑：tsx（以及 Node）默认不会自动加载 .env 文件。如果你只是把 Key 写进 .env 就直接运行，process.env.DEEPSEEK_API_KEY 依然是空的，DeepSeek 会返回 401 Authentication Fails（auth header format should be Bearer sk-...）——这不是 Key 写错了，而是根本没被读进来。

解决办法：装上 dotenv，并在入口文件最顶部（早于任何其他 import）加载它：

npm install dotenv
// main.ts —— 必须是第一行 import，否则读取时变量还没加载进来
import "dotenv/config";

import { Agent } from "./agent.ts";
import { DeepSeekModel } from "./model.ts";
// ...

const agent = new Agent(
  { model: new DeepSeekModel(process.env.DEEPSEEK_API_KEY ?? "") },
  tools,
);
🔐 .env 里是真实密钥，永远不要提交到版本库。把 .env 写进 .gitignore，只提交不含密钥的 .env.example 作为模板。

为什么工具执行失败时不应该直接抛出异常终止循环？
